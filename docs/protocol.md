# Прошивка 0.3.0 и протокол

Плата: ESP32 classic ESP-WROOM-32. Сборка `pio run` (PlatformIO, окружение esp32dev). Прошивка USB после проверки конкретной платы: `pio run -t upload --upload-port COM…`; сейчас загрузка в устройство не выполнялась.

## Подключение

BLE имя ThreadWinder, сервис `7b4e0001-6b2d-4e53-9c71-9a03f30c8a10`, RX write `7b4e0002-6b2d-4e53-9c71-9a03f30c8a10`, TX notify/read `7b4e0003-6b2d-4e53-9c71-9a03f30c8a10`. UTF-8 JSON, каждое сообщение заканчивается LF. Вход до 2048 байт, выход разбивается на уведомления по 20 байт; клиент собирает до LF. Один клиент должен последовательно отправлять команды и ждать ответы. Не использовать раздельные незавершённые сообщения от нескольких клиентов одновременно.

Запасная сеть Wi-Fi: `ThreadWinder`, пароль `winding12345`, страница `http://192.168.4.1`. `GET /api/status`, `POST /api/command` с Content-Type application/json. Интернет для локальной страницы не нужен. Для Bluetooth через веб Chrome требуется HTTPS или localhost; GitHub Pages предоставляет HTTPS. Потеря связи с сайтом не останавливает станок: сохранённая программа выполняется самостоятельно, физические кнопки остаются активны.

Команды: `{"cmd":"get","id":1}`, `start`, `pause`, `resume`, `reset`, `home`, `config`. Последняя имеет объект `config`, содержащий изменяемые поля. Ответ повторяет id и содержит ok, при успехе полное состояние; при отклонении ok=false и error. BLE также сообщает состояние раз в секунду. ACK config отправляется только после проверки записи всех настроек в NVS и чтения их обратно. Во время работы настройки менять нельзя, даже скорость: сначала сбросить/завершить работу. Ошибки настройки не вызывают движение.

## Все сохраняемые настройки

| maxRpm | 120 | 1–150 об/мин |

| threadMm | 0,11 | 0,02–1 мм |

| leadMm | 4 | 1–20 мм/оборот винта |
| homeSpeedMmS | 2 | 0,1–5 мм/с |
| homeAccelMmS2 | 2 | 0,1–10 мм/с² |

| homeLatchMmS | 0,5 | 0,1–1 мм/с, не больше homeSpeedMmS |

| invertSpindle | false | bool |

| commissioned | false | bool; разблокировка после проверки подключения |
| limitNormallyOpen | true | bool; true = COM–NO (нажат LOW), false = COM–NC (нажат HIGH) |

Ограничение частоты каждой оси 8000 импульсов/с. Дополнительно проверяются взаимные ограничения хода/отступа/ширины/отхода. Неизвестные ключи отклоняются. Сохранение версионировано schema=2. Запись schema=1 с 21 полем читается с прежней полярностью NC (limitNormallyOpen=false); новые настройки по умолчанию используют COM–NO (limitNormallyOpen=true). Отсутствующая, неверная или неполная запись включает безопасные заводские настройки с commissioned=false. При обрыве питания незавершённая намотка не возобновляется и её счётчик не восстанавливается.

## Поведение

Первое включение с отсутствующими или неверными настройками заблокировано (commissioned=false). После проверки монтажа и сохранения commissioned=true двигатели переходят на удержание, затем нужно отдельно выполнить Home. На последующих включениях поиск исходного положения начинается автоматически, без сайта. Изменение шагов, микрошагов, шага винта, направления каретки или полярности концевика сбрасывает найденный ноль; изменение только длины/скорости его сохраняет.

По USB Serial 115200 доступен только запрос состояния `{"cmd":"get","id":1}` одной JSON-строкой с LF. Другие команды по USB отклоняются. Диагностический режим проверки кнопок, счётчики и команды test из рабочей версии удалены.

Концевик COM–NO подключён к GND, вход с подтяжкой. По умолчанию limitNormallyOpen=true: нажатию соответствует LOW. Для COM–NC выбрать limitNormallyOpen=false: нажатию соответствует HIGH. При NO обрыв провода неотличим от отпущенного концевика, поэтому сначала обязательно проверить вход вручную. Поиск: ограниченное освобождение при нажатом концевике → поиск влево → отход вправо → медленный повторный подход → установка координаты 0 → финальный отход вправо на homeBackoffMm. Завершённый возврат оставляет каретку рядом с концевиком, а не зажатой на нём. Домашние решения фильтруются 5 мс, неожиданный концевик при обычном движении вызывает немедленную ошибку. Такой останов защитный, не плавный. Длина/время поиска ограничены, но не заменяют правильное направление и физические упоры.

Start перемещает каретку к homeOffsetMm и запускает намотку. Каждый полный проход имеет длину widthMm. У края обе оси вместе плавно доходят до нулевой скорости; только затем меняется направление каретки. Это сохраняет синхронизацию без наматывания лишних витков на краю, но создаёт краткую остановку шпинделя на каждом развороте. Его направление никогда не меняется. Последний проход может быть неполным, затем выполняется Home.

Короткое нажатие GPIO33: Start / Pause / Resume. Удержание 1,8 с: плавная остановка и сброс текущей намотки без возврата. GPIO21: плавная остановка намотки и Home. Прерывание самого поиска Home сбросом останавливает его немедленно и делает координату неизвестной. Каретка и шпиндель остаются под током после разблокировки; экономичного снижения тока A4988 программно не поддерживает. Отключение питания снимает удержание.

## Расчёт длины и проверка

Используется модель роста эффективного диаметра: L = factor × π × (core×N + thread×pitch/width×N²)/1000, где N — фактически выданные обороты шпинделя. Она приближённая: не измеряет натяжение, проскальзывание, реальный диаметр и уплотнение, не учитывает малую добавку от спирали. Считаются и витки торможения. Нужна калибровка по измеренной нити: новый lengthFactor = старый × фактическая длина / показанная длина.

Таймер ESP32 25 кГц формирует импульсы независимо от сети, целочисленный DDA синхронизирует оси; планировщик обновляет общий разгон/торможение примерно раз в 1 мс. Аппаратно проверить осциллографом STEP, направление, питание, нагрев и отсутствие пропусков ещё предстоит. Команды программы не заменяют выключатель питания.

`node tests/motion.test.cjs` выполняет фактические выражения расчёта из заголовка и извлечённое тело обработчика DDA в хостовой модели: инверсия длины, количество импульсов и их минимальные интервалы, пауза/продолжение, пределы движения и ускорение. Это не испытание ESP32 или реальной механики.
