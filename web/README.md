# Страница управления

Файлы для размещения: `index.html`, `style.css`, `app.js`, `transport.mjs`. Их нужно копировать вместе, сохраняя имена. Зависимостей и сборки у страницы нет. Та же страница встраивается в прошивку ESP32. Тесты, снимки экрана и этот файл размещать на сайте не требуется.

## Подключение

На GitHub Pages открыть страницу по HTTPS в Chrome на Windows или Android, нажать Bluetooth и выбрать ThreadWinder. Подключение выбирается заново после закрытия страницы; настройки станка загружаются из ESP32, не из браузера. Состояние и длина появляются только из ответов устройства; демонстрационного движения на рабочей странице нет.

Для Wi-Fi подключиться к сети `ThreadWinder`, пароль `winding12345`, и открыть `http://192.168.4.1`. На этой странице соединение Wi-Fi выбирается автоматически. GitHub-страница не обращается к локальному HTTP-адресу: для запасного способа нужно открыть страницу, которую раздаёт сам станок.

При потере соединения кнопки сайта блокируются. Команды автоматически не повторяются после переподключения. Если команда не подтверждена, сначала проверить фактическое состояние станка. Физическая кнопка требуется для остановки при потере связи. Поведение движения при потере связи определяет прошивка.

## Настройки и первичная проверка

Расширенное меню скрыто: нажать пять раз на название «Намотчик» за 2,5 секунды; с клавиатуры — пять нажатий Enter на заголовке. При остановленном станке в меню видны параметры механики, направления, скорость поиска концевика, микрошаги, калибровка длины и разрешение первого запуска. Показания концевика доступны и в основном интерфейсе.

Пока проверка подключения не завершена в настройках ESP32, запуск и возврат с сайта заблокированы. После сохранения разрешения нужно выполнить возврат к концевику. При последующих включениях ESP32 автоматически ищет концевик перед работой. Концевик пользователя подключён к COM–NO: при нажатии контакты замыкаются. В расширенных настройках сохраняется выбор типа контактов «Концевик подключён к COM–NO». Для NC нужно снять этот флажок. Микрошаги в форме должны совпадать с аппаратными перемычками. Ток A4988 регулируется на драйвере, программной регулировки тока у него нет.

Длина — на каждую нить. Кнопка «Начать намотку» применяет текущую длину и скорость перед стартом. На паузе параметры не меняются, «Продолжить» сохраняет текущую намотку. «Сброс» останавливает на месте; «Вернуться к концевику» возвращает каретку. Пауза доступна и при перемещении к началу намотки.

Настройки сохраняются в энергонезависимой памяти ESP32 после нажатия кнопки применения. Подтверждение «сохранены» появляется после положительного ответа контроллера о проверенной записи в память. При новом подключении форма загружается из контроллера. Состояние текущей намотки после отключения питания не восстанавливается.

## Протокол

HTTP: `GET /api/status`, `POST /api/command` с JSON. Оба пути относительные к странице на станке.

BLE service `7b4e0001-6b2d-4e53-9c71-9a03f30c8a10`, RX `7b4e0002-6b2d-4e53-9c71-9a03f30c8a10` (write with response), TX `7b4e0003-6b2d-4e53-9c71-9a03f30c8a10` (notify). JSON UTF-8 заканчивается переводом строки; записи разбиваются на фрагменты не более 20 байт. Парсер сохраняет незавершённые символы UTF-8 между уведомлениями. Пользовательские BLE-команды содержат числовой `id`; сайт ждёт соответствующий ответ `ok` и показывает отклонения и таймауты. Периодический статус без `id` не является подтверждением команды.

## Проверки без оборудования

`node tests.mjs` проверяет UTF-8 и фрагментацию BLE, размеры команд и диапазоны рецепта. `node browser-test.cjs` и `node ble-browser-test.cjs` проверяют интерфейс в локальном Chrome с подставным контроллером. В путях к Chrome и Playwright в этих двух тестовых файлах указан компьютер разработки. Эти проверки не заменяют испытание с ESP32, драйверами и двигателями.

`preview-desktop.png` и `preview-mobile.png` — изображения интерфейса во время проверки с подставным контроллером, не показания подключённого станка.
